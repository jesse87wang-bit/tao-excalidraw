# tao-excalidraw

把一篇中文口播稿转成“可编辑信息图 + 每段一张稚拙手绘插画”的完整交付包。严格执行“确认绘制逻辑 → 确认统一尺寸 → 正式绘制”的流程。

## 启动规则

1. 收到新口播稿后，先判断稿件的自然叙事段落，不预设固定为六段或七段。
2. 若文案足以分析，不追问无关信息；从标题和主旨推断项目主题与文件名。
3. 第一轮只执行阶段 A。不得调用生图工具，不得创建最终 Excalidraw，不得用“先做一版”代替确认。
4. 用户对阶段 A 回复“确认”“可以画”“按这个做”等明确授权后，不立即绘制；先执行阶段 A.5，询问统一成品尺寸。
5. 用户提出修改时，先更新绘制逻辑，再停下来等待新的明确确认。
6. 新聊天、新稿件必须重新走阶段 A；其他聊天里的确认不能自动沿用。
7. 每个新稿件或新一轮图片生成批次都必须重新询问统一尺寸；不得默认沿用上一个项目、上一轮或其他聊天的尺寸。
8. 即使用户在最初需求里写过尺寸，也要在阶段 A 确认后复述该尺寸并请求一次明确确认。
9. 未同时获得“绘制逻辑确认”和“统一尺寸确认”前，不得调用生图工具，不得生成插画，不得制作最终 Excalidraw 或导出成品图。

## 阶段 A：提交绘制逻辑

先完整阅读口播稿，保留原论点、因果关系和语气，不擅自替作者增加结论。按自然叙事逻辑拆段，每段输出：

- 段落编号与标题
- 本段核心信息／观众应记住的一句话
- 上半部分信息图逻辑：采用时间线、对比、汇聚、发散、循环、漏斗、天平、流水线等哪种结构，以及节点关系
- 下半部分插画镜头：人物、动作、道具、场景和视觉隐喻
- 需要核实或谨慎呈现的公式、数据、事实与假设

最后补充全稿统一规则：段数、纵向阅读顺序、颜色语义、插画人物连续性和预计交付文件。此阶段只向用户展示方案，并以一句简短请求结束，例如“如果这套逻辑没问题，回复‘确认’，我再确认统一图片尺寸。”

遇到定价、医疗、法律、金融或其他需要高准确度的内容时，先用适合的领域技能或权威来源核验关键主张；把推断标明为推断，不把假设画成事实。

## 阶段 A.5：确认统一图片尺寸

用户确认绘制逻辑后，必须单独询问，随后停止并等待答复：

> 请确认本次所有分段完整成品图（每段的信息图＋插画）统一采用什么尺寸？请回复“比例＋像素”，例如 3:2（1536×1024）、3:4（1536×2048）或 9:16（1080×1920）。

执行规则：

- 一次确认覆盖本轮全部段落，所有段必须采用同一个成品尺寸。
- 用户只给比例时，提出一个对应的准确像素尺寸并再次等待确认，不自行决定。
- 用户此前已经写过尺寸时，复述为“本次统一按……，确认吗？”，得到明确答复后再继续。
- 把确认结果记录为 `统一成品尺寸：<宽> × <高>（<比例>）`。该尺寸指每段完整成品图和手机分段预览，不自动等同于下半部分原始插画文件的画幅。
- 若用户明确要求原始插画也使用同一尺寸，则一并遵循；否则根据成品画布内的插画区选择合适画幅，且不得裁切主体。
- 用户改变尺寸即视为新一轮生成批次；先确认新尺寸，再重新绘制或重排。

## 阶段 B：逻辑与尺寸均确认后正式绘制

用户同时确认绘制逻辑和统一成品尺寸后，先阅读并遵循：

- `references/visual-spec.md`：画幅、画风、角色、配色和构图规范
- `references/delivery-spec.md`：制作、验证、命名和交付规范
- `assets/layout-reference.png`：只参考主标题层级、单段密度和相邻段落间的纯白留白比例；不得复制其中的具体文字、插画场景或旧版构图

### 跨宿主适配

- 先把当前 `SKILL.md` 所在目录解析为 `TAO_SKILL_DIR`。本 Skill 中的 `references/...`、`assets/...`、`scripts/...` 均相对该目录，而不是相对工作区当前目录；不得写死 `~/.codex`、`~/.claude` 等宿主路径。
- 阶段 B 只依赖四类能力：参考图生图、图像查看、Excalidraw JSON 构建与渲染、文件打包。优先使用当前宿主已有的等价能力；`jacky-illustration`、`imagegen` 和 `excalidraw-diagram` 是可选适配器，不是必须存在的依赖。
- 宿主没有 `excalidraw-diagram` 时，使用其文件或代码能力直接创建有效的 Excalidraw JSON，并严格遵守本 Skill 的参考规范；不得因此把文字烘焙进插画或牺牲可编辑性。
- 正式绘制前检查能力。若缺少参考图生图能力，或无法产出、渲染 Excalidraw，不得假装完成；说明缺少的能力，请用户提供插画、启用等价工具，或明确授权仅交付当前可生成的部分。
- 校验脚本需要能执行 `.mjs` 的 Node.js，建议使用 Node.js 18 或更高版本。宿主不支持内嵌图片或本地可点击链接时，交付该宿主可访问的文件路径和清单，不声称已经在对话中展示。

然后按以下顺序工作：

1. 使用宿主可用的参考图生图能力生成每段一张插画；可用时优先调用 `jacky-illustration` 或 `imagegen`。以 `assets/style-anchor.png` 为风格锚点，只借鉴媒介质感与稚拙程度，不复制其中人物、构图或文字；画幅按阶段 A.5 的确认结果与插画区构图执行。
2. 每生成一张都用图像查看工具目检；发现文字、水印、比例错误、画面语义错误、人物不一致或画风过于光滑时，立即迭代。
3. 使用宿主可用的 Excalidraw 构建与渲染能力制作纵向长画布；可用时优先调用 `excalidraw-diagram`，否则直接构建 Excalidraw JSON。每段默认采用“上方信息流程约 2/3 → 中间手绘插画 → 底部一句收束文字”的三层结构；下方约 1/3 是包含插画与底部收束句的视觉区，不把收束句另算成第四块高度。所有标题、解释、公式和数字都用 Excalidraw 原生文本，不烘焙进插画。完整长图中，相邻两个单段区块之间必须插入约 `0.26H` 的纯白段间留白；单段图和手机预览仍保持精确 `W × H`，不把这段留白算入单段尺寸。
   - 原生元素必须使用 `references/visual-spec.md` 中的“Excalidraw 原生元素默认样式”。所有文本一律使用 Excalifont（`fontFamily: 5`），不得由系统默认字体、Virgil、Helvetica 或 Cascadia 代替。
   - 每段第一句作为主标题，按 `references/visual-spec.md` 的自适应字号与宽度规则排版；默认字号约为 `0.052W`，实际渲染宽度不得超过 `0.86W`。
   - 把段号、主标题和副标题组成独立标题区：主标题顶部位于约 `0.04H–0.06H`；主标题与副标题之间留 `0.018H–0.03H`；副标题结束后再留 `0.044H–0.085H` 的纯白呼吸带，才进入第一个信息模块。不得让流程卡贴着副标题。
   - 中文采用 Excalifont 的自然字距；不得通过在汉字之间插入空格、压缩文本框或横向拉伸来“做字距”。副标题和首个信息模块分别标记 `taoRole: "section-subtitle"` 与 `taoRole: "section-content-start"`，供布局校验器检查。
4. 把所有插画作为 data URL 嵌入 `.excalidraw` 的 `files` 对象，确保文件离线打开不丢图。
5. 渲染完整长图和手机分段图，逐张目检并修复拥挤、遮挡、裁切、小字或错误连线。
6. 执行结构检查，确认元素 ID 唯一、图片 `fileId` 有映射、透明度为 100、图片数量与段数一致；依次运行 `node "<TAO_SKILL_DIR>/scripts/validate-excalidraw-defaults.mjs" <成品.excalidraw>` 和 `node "<TAO_SKILL_DIR>/scripts/validate-tao-layout.mjs" <成品.excalidraw>`，确认 Excalifont、默认元素样式、主标题宽度与字号、段间留白全部通过。
7. 打包完整交付目录和 ZIP。宿主支持对话内图片展示时直接展示手机分段预览；否则提供该宿主可访问的预览文件路径和清楚的文件清单。

## 内容与版式原则

- 一段只讲一个中心意思；信息图负责“逻辑”，插画负责“理解和记忆”。
- 除非用户在当前任务明确指定其他布局，每段按画布高度执行默认 `2:1` 分配：上方约 `64%–67%` 为信息流程区；下方约 `33%–36%` 为视觉收束区。视觉收束区内先放等比手绘插画，最后 `4%–6%` 画布高度放一行居中的文字表述句。也就是说，“插画约 1/3”包含插画周围必要留白和底部收束句。
- 信息流程区必须形成有层级、有呼吸感的视觉组：标题／副标题先独立成组，副标题后保留 `4.4%–8.5%H` 空白，再进入核心对比或流程；常规页优先取约 `5.5%–6%H`。同级模块保持稳定间隔，不把文字、箭头和卡片挤成一团。除标题呼吸带和有意设计的组间停顿外，单条连续空白带原则上不超过 `8.5%H`；出现无意义空洞时再重排内容，而不是机械放大元素。
- “单段内部留白”和“长图段间留白”必须区分：单段内部继续紧凑；只有完整长图中相邻段落之间保留大块纯白呼吸区。默认段间留白 `S = round(0.26H)`，允许范围为 `0.24H–0.30H`，用户在当前任务明确指定时才覆盖。
- 每段第一句必须作为最醒目的主标题。先按 `clamp(round(0.052W), 56, 96)` 设置字号，再根据 Excalifont 的实际文本边界缩小，确保标题宽度不超过 `0.86W`、左右各保留至少约 `7%W` 的安全边距；不得把标题裁切在画布外。
- 主标题和副标题均保持 Excalifont 自然字距与 `autoResize: true`。主标题多行时使用 `1.15–1.25` 行高，副标题使用 `1.25–1.35` 行高；不在中文字符间人为加空格，不让文字紧贴卡片边框。
- 插画位于信息流程之后、底部文字之前，保持原始宽高比并水平居中；底部文字只保留一句本段的最终判断或记忆句，不与插画重叠。
- 信息图使用原生形状、箭头和文本，保持可编辑；插画内部不出现可读文字、字母、数字、Logo 或水印。
- 除非用户在当前任务明确覆盖，原生元素默认采用：实心填充、2 px 描边、实线边框、粗糙度 2、圆角矩形、曲线箭头、末端箭头、居中文本、100% 透明度；所有文本强制使用 Excalifont（`fontFamily: 5`）。
- 每段完整成品图和手机分段预览必须精确使用本轮已确认的统一尺寸，不预设 3:2、3:4、9:16 或固定像素。
- 插画在每段内居中放置，尺寸根据已确认画布自适应，四周保留少量稳定白边；不得拉伸、压扁或裁切主体。
- 若口播主体需要“老板”角色，则保持同一形象贯穿全稿，但每段动作、道具和场景随内容变化；其他题材按原稿选择连续主角，不强行添加老板。
- 不为了“好看”添加与论点无关的装饰，不把复杂口播逐字塞进画面。

## 交付回复

交付时先说明已完成，再给出以下交付文件：

- 可编辑 `.excalidraw`
- 完整长图 PNG
- ZIP 完整包
- 交付说明

简要列出统一成品尺寸、段数、插画数、手机预览位置和已完成的验证。宿主支持对话内图片展示时，必须把分段预览直接显示；宿主不支持时，提供其可访问的路径和逐张文件清单。
