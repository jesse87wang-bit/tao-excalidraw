# 制作与交付规范

## 阶段 A 输出模板

```markdown
主题：……
建议拆成 N 段

01｜段落标题
- 核心信息：……
- 信息图逻辑：……
- 插画镜头：……
- 准确性提醒：……（没有则写“无”）

……

统一视觉规则：……
预计交付：……

如果这套逻辑没问题，回复“确认”，我再确认统一图片尺寸。
```

阶段 A 不生成文件、不生成示意图、不把确认问题隐藏在长篇说明中。

## 阶段 A.5 尺寸确认模板

绘制逻辑获得明确确认后，单独发送：

```markdown
请确认本次所有分段完整成品图（每段的信息图＋插画）统一采用什么尺寸？
请回复“比例＋像素”，例如：
- 3:2（1536 × 1024）
- 3:4（1536 × 2048）
- 9:16（1080 × 1920）
```

发送后停止，等待用户明确回复。即使需求中已经出现尺寸，也要复述并确认；只给比例时，提出准确像素方案并再次确认。确认后把结果写入制作记录：

```text
统一成品尺寸：<宽> × <高>（<比例>）
```

该记录是本轮所有分段 Excalidraw 区块、分段 PNG 和手机预览的唯一尺寸真源。未形成该记录前不得进入阶段 B。

## 阶段 B 文件结构

默认在当前工作区创建以下目录；若同名已存在，使用清楚的版本后缀，不覆盖用户现有成果：

```text
<主题>-完整交付/
├── <主题>-口播稿视觉图-<N>段稚拙手绘版.excalidraw
├── <主题>-口播稿视觉图-<N>段稚拙手绘版.png
├── <主题>-完整交付.zip
├── 交付说明.md
├── <主题>手绘插画/
│   ├── 01-<段落简称>.png
│   ├── ...
│   └── 提示词.md
└── <主题>手机端预览/
    ├── 01-<段落简称>.png
    └── ...
```

ZIP 放在交付目录内时，创建压缩包要排除 ZIP 自身，避免递归包含。

## Excalidraw 构建检查

- 每个区块含原生标题、信息图和一张图片元素。
- 每个区块和每张手机分段 PNG 都精确匹配已确认的统一宽、高和比例。
- 完整长图相邻区块之间的纯白留白默认为 `0.26H`，且处于 `0.24H–0.30H` 验收范围；单段 PNG 和手机预览不包含这段额外留白。
- 每段存在一个锁定、白底、带 `customData.taoRole: "section-frame"` 的 `W × H` 边界矩形；相邻边界矩形之间不得出现任何可见元素。
- 每段第一句的原生文本带 `customData.taoRole: "section-title"`；主标题使用 Excalifont，实际宽度不超过 `0.86W`，居中且字号符合自适应下限。
- 图片元素保持原始比例并在下半部分自适应居中，不拉伸、不压扁、不裁切主体。
- `files` 中存在每张图的完整 data URL；每个图片元素的 `fileId` 都能找到对应文件。
- 文字使用可读字号，移动端预览中不出现需要放大多次才能看清的关键字。
- 形状、箭头、文本不遮挡；箭头终点清楚；段间留白稳定。
- 所有元素 `opacity` 为 100；元素 ID 唯一。
- 所有原生 `text` 元素必须为 Excalifont，即 `fontFamily` 严格等于 `5`；不得只凭渲染外观判断字体。
- 原生形状和箭头默认符合 `visual-spec.md` 的截图锁定样式；语义性例外必须使用 `customData.taoStyleExempt: true` 并注明 `reason`。
- 图片元素数量、内嵌文件数量和自然段数量一致。

## 验证闭环

先把当前 `SKILL.md` 所在目录解析为 `TAO_SKILL_DIR`。以下脚本路径都从该目录解析，不从当前工作目录解析；运行脚本需要能执行 `.mjs` 的 Node.js，建议使用 Node.js 18 或更高版本。

1. 验证 `.excalidraw` JSON 可解析。
2. 校验唯一 ID、图片数量、`fileId` 映射、data URL 和透明度。
3. 运行 `node "<TAO_SKILL_DIR>/scripts/validate-excalidraw-defaults.mjs" <成品.excalidraw>`，确认所有文本均为 `fontFamily: 5`，并检查默认填充、描边、粗糙度、圆角与曲线箭头。
4. 运行 `node "<TAO_SKILL_DIR>/scripts/validate-tao-layout.mjs" <成品.excalidraw>`，确认区块边界、`0.24H–0.30H` 段间留白、纯白空区、主标题字号和 `0.86W` 最大宽度。
5. 用 `sips`、ImageMagick 或等效工具核对每张分段 PNG 的像素尺寸，确认全部与 `统一成品尺寸` 完全一致。
6. 按 `N × H + (N - 1) × S` 核对完整 PNG 高度；宽度必须等于 `W`。
7. 用图像查看工具检查完整长图；重点看首屏、每一个段间大留白、最密集区和末屏。
8. 导出每段手机预览并逐张目检，确认主标题在手机端仍明显大于其他文字且不越界。
9. 如有尺寸错误、机械裁切、拉伸、段间留白不足或被占用、主标题太小或越界、文字覆盖、连线错误、字体不是 Excalifont 或插画语义不符，修改后重新渲染，直到通过。

## 交付说明内容

`交付说明.md` 至少包括：

- 项目主题、段数和制作日期
- 本轮确认的统一成品尺寸与比例
- 每段标题与对应插画文件
- `.excalidraw`、完整 PNG、手机预览、原图、提示词、ZIP 的位置
- 画幅与风格说明
- 已完成的结构和视觉验证
- 在 Excalidraw 中继续编辑的方法

## 对话交付

若宿主支持本地可点击链接和对话内图片展示，最终回复先给出可编辑文件、完整 PNG、ZIP 和交付说明的可点击路径，再简要说明验证结果，并直接显示所有手机分段 PNG。若宿主不支持这些界面能力，改为提供该宿主可访问的工作区路径、逐张文件清单和验证结果；不得声称已经内嵌展示。
